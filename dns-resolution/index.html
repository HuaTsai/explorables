打開一個網址之前,瀏覽器得先把名稱換成 IP 位址。按「下一步」看這個問題被問了幾次、誰回答了什麼。

誰在回答問題

你的電腦只問一台伺服器:遞迴解析器,通常是網路業者提供的,或 1.1.1.1、8.8.8.8 這類公用的。真正跑去問一圈的是它。

DNS 是一棵樹,每一層伺服器只知道下一層該問誰。根伺服器知道 .dev 歸誰管,.dev 伺服器知道 huatsai.dev 歸誰管,最後那台權威伺服器才有真正的紀錄。下圖用兩種顏色區分 問 和 答。

      這個模型省略了什麼
      
    
        
      
      • 這個站實際上開了 Cloudflare 的 proxy(橘色雲)。開了之後權威伺服器不會回 CNAME,而是直接回 Cloudflare 自己的 A 和 AAAA。這裡畫的是 DNS only(灰色雲)的情況。
        • 
      
      • 沙盒裡只有 .dev 和 .io 兩個頂級網域,底下各一個網域。每個網域實際上有好幾台名稱伺服器,這裡只列一台。
        • 
      
      • 解析器拿到 NS 紀錄後,還得知道那台伺服器的 IP。這通常由同一個回應附帶的 glue 紀錄提供,這裡略過。
        • 
      
      • NXDOMAIN 和空答案實際上也會被快取一段時間(負快取),這裡不會。
        • 
      
      • 同一個 zone 內的 CNAME 鏈,真實的權威伺服器通常在一次回應裡就附上後續紀錄。這裡每一跳都重新查詢,比較容易看清楚。
        • 
      
      • 新的解析器會做 QNAME minimization:問根伺服器時只問 dev,不透露完整名稱。這裡每次都問完整的名稱。
        • 
      
      • 瀏覽器和作業系統自己也有一層快取。DNSSEC 完全沒有畫。
