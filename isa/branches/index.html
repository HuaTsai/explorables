條件分支 flags 與比較跳轉合一

一個 if (a < b) 在 x86 和 ARM 上是兩條指令：先比較，把結果寫進一個隱藏的 flags 暫存器，再由跳轉指令讀出來。RISC-V 沒有這個暫存器，比較和跳轉是同一條。輸入 a、b，按「下一步」看 flags 怎麼被寫、怎麼被讀，以及有號和無號差在哪一個 bit。

兩種模型

x86-64 和 AArch64：比較寫 flags，跳轉讀 flags。cmp a, b 做一次減法 a − b，結果本身丟掉，只把結果的四個性質寫進 flags 暫存器（x86 叫 RFLAGS，ARM 叫 NZCV）：

  • ZF / Z（zero）：結果是不是零。a == b 就看它。
  • SF / N（sign / negative）：結果的最高 bit，也就是把結果當有號數時是不是負的。
  • OF / V（overflow）：把兩邊當有號數時，減法有沒有溢位。例如 −263 − 1 會溢位成正數。
  • CF / C（carry）：把兩邊當無號數時有沒有借位。這一個 x86 和 ARM 定義相反：x86 的 CF=1 表示有借位（a < b 無號），ARM 的 C=1 表示沒有借位（a ≥ b 無號）。

接著跳轉指令挑它需要的 flag 來看。有號的「小於」不能只看 SF，因為溢位會把符號翻掉，正確公式是 SF ≠ OF（ARM：N ≠ V）。無號的「小於」只看借位：x86 CF = 1，ARM C = 0。相等看 ZF = 1。

RISC-V：比較和跳轉是同一條。blt a0, a1, L 讀兩個暫存器、做有號比較、成立就跳。沒有 flags 暫存器，沒有「上一條指令留下的狀態」這回事。無號版本是 bltu，相等是 beq。代價是一條分支指令要塞兩個 5 bit 的暫存器欄位，位移只剩 12 bits（±4 KB）；x86 和 ARM 的條件跳轉不帶暫存器，位移可以更遠。

沒有 flags 的代價與好處

    
flags 最有用的地方不是分支，是多字長算術。兩個 128 位元數相加，低 64 位元相加產生的進位要加到高 64 位元。x86 和 ARM 的加法指令順手把進位寫進 CF / C，下一條 adc（add with carry）直接讀。RISC-V 沒有地方放進位，要自己算：低位相加之後，如果結果比其中一個加數還小，就是繞回了，也就是有進位。sltu 做這個比較，多出兩條指令。

  

  

    

      
x86-64


mov rax, rdi
add rax, rdx   ; 寫 CF
adc rsi, rcx   ; 讀 CF
mov rdx, rsi
ret

      
add 和 adc 之間靠 CF 傳遞進位。中間不能插任何會改 CF 的指令。

    

    

      
AArch64


adds x0, x2, x0   // 寫 C
adc  x1, x3, x1   // 讀 C
ret

      
ARM 的 add 預設不碰 flags，要寫 flags 得用 adds（加 s 後綴）。兩條指令做完 128 位元加法。

    

    

      
RV64GC


add  a0, a0, a2
add  a1, a1, a3
sltu a2, a0, a2   # a0 < a2 ⇒ 進位
add  a1, a1, a2
ret

      
進位是一個普通的暫存器值，用 sltu 算出來再加上去。四條指令，沒有隱藏狀態。

    

  

  

    
反過來看，flags 是一個所有算術指令都在寫的共用暫存器。亂序執行的核心要把它當成一個真正的暫存器來改名（rename），不然每條 add 都要等前一條 add 寫完 flags。更麻煩的是 x86 有些指令只改部分 flags（inc 不碰 CF），讀 flags 的指令就得把兩個來源合併，早年的 Pentium 4 為此付出過停頓。RISC-V 選擇不要這個暫存器，多字長算術多付兩條指令，換取每條指令的依賴關係都明明白白寫在暫存器編號裡。

  


  

    
看完可以帶走的三句話

    
    
      
  1. flags 是一個隱藏的共用暫存器。它不出現在組語的運算元裡，但 cmp 寫它、jcc 讀它、add 也寫它。硬體要追蹤這個看不見的依賴，編譯器排程時要小心別在中間插入會改它的指令。
    2. 
      
  2. RISC-V 把比較和跳轉綁在一起，用編碼空間換掉一整個狀態暫存器。分支指令多塞兩個 5 bit 的暫存器欄位，位移縮到 12 bits，但每條指令的輸入輸出都在暫存器編號裡，沒有隱藏狀態。
    3. 
      
  3. 有號和無號的差別只在看哪個 flag。同一條 cmp，看 SF 和 OF 是有號比較，看 CF 是無號比較。C 語言裡 long 和 unsigned long 的 < 編出來的 cmp 一模一樣，只有後面的跳轉指令不同。

這個模型省略了什麼

    
    
      
  • 條件搬移。短的 if 常被編成不跳轉的形式：x86 的 cmov 和 setcc、ARM 的 csel 和 cset、RISC-V 的 slt 加算術或 Zicond 擴充的 czero。這一頁用 *p = 1 這種有副作用的寫法逼編譯器產生真正的分支。
    • 
      
  • 其他會寫 flags 的指令。x86 的 test（做 AND 只留 flags）、ARM 的 tst 和 ccmp（條件比較，可以把兩個條件串成一次跳轉），以及所有算術指令。
    • 
      
  • 分支預測。三邊的硬體都在跳轉指令執行前就猜方向、先跑下去，猜錯再回頭。這一頁的「跳或不跳」是最終結果，不是硬體當下的猜測。
    • 
      
  • 專用的零比較。AArch64 有 cbz / cbnz（暫存器是不是零就跳）和 tbz / tbnz（某個 bit 是不是零就跳），不經過 flags。RISC-V 的 beqz、bnez、bltz 是偽指令，展開成和 x0 比較。
    • 
      
  • x86 的 flags 不只四個。還有 PF（parity）、AF（輔助進位，BCD 用）、DF（字串方向）等，以及控制中斷和特權的位元。這裡只看分支會用到的四個。
