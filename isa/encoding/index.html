指令編碼 定長與變長

CPU 從記憶體拿到的只是一串 byte。解碼器的第一個問題不是「這條做什麼」，而是「這條到哪裡結束」。按「下一步」把同一段 C 編出來的機器碼一次一個 byte 餵給三個 ISA 的解碼器，看誰什麼時候才知道長度。

解碼器先要知道這條有多長

CPU 執行指令前要先找到它的邊界：這條從哪個 byte 開始、到哪個 byte 結束，下一條才知道從哪裡接。對三個 ISA 來說，這件事的難度完全不同：

  • x86-64：一條指令 1 到 15 bytes。要讀 prefix、opcode，有時還要讀 ModRM 和 SIB，才知道後面還有沒有位移和立即值。長度是一邊讀一邊發現的。
  • AArch64（64 位元 ARM）：每條固定 4 bytes。不用讀內容就知道邊界，一次抓 32 bytes 就是 8 條指令，可以同時解碼。
  • RISC-V（RV64GC）：基本指令 4 bytes，加上 C 擴充後常用指令可以壓成 2 bytes。看第一個 byte 的最低 2 bits 就知道是哪一種。

下面四個案例都是一兩行 C，用 clang 23 以 -O2 編成三種目標的機器碼，byte 是 llvm-objdump 印出來的，不是手寫的。x86 以 Intel 語法顯示（目的在左）。三條帶子各有自己的節拍：x86 一步讀 1 byte，AArch64 一步讀 4 bytes，RISC-V 先偷看 2 bits 再讀整條。步數本身就是故事的一部分。

結語

    
三種編碼換的是不同的東西。x86 的變長編碼換密度：常用的短、少用的長，像霍夫曼編碼，代價是解碼器讀到 ModRM 之前不知道這條有多長，想同時解碼多條就得猜邊界，現代核心靠 µop cache 繞過這個瓶頸。AArch64 的定長編碼換解碼平行度：拿到 32 bytes 就知道有 8 條，欄位位置固定，代價是 ret 也要 4 bytes。RISC-V 用兩種長度折衷：看 2 bits 就知道長度，常用指令壓到 2 bytes，但 16 位元放不下三個 5 bit 的暫存器編號，壓縮指令只能用 8 個熱門暫存器或讓目的和來源共用。

    
編碼長度直接決定了兩件事：指令裡放得下幾個暫存器編號，以及放得下多大的常數。前者是暫存器那一篇，後者是立即值那一篇。解碼器拆出來的東西進了核心之後會變成什麼，見 micro-op。

    
這一頁一次解一個 byte，而且只碰到最簡單的前綴，和真實解碼器差了幾件事：

    
    
      
  • x86 的前綴遠不止 REX。還有 operand-size、segment、LOCK、REP 等舊前綴，以及 SIMD 用的 VEX（2 到 3 bytes）和 EVEX（4 bytes），一條 AVX-512 指令輕易超過 10 bytes。
    • 
      
  • 真實解碼器一個 cycle 抓 16 或 32 bytes，用平行的長度預測器同時猜好幾個起點再丟掉猜錯的。一步一 byte 只是為了讓「什麼時候才知道長度」看得見。
    • 
      
  • 32 位元 ARM 的 Thumb-2 混用 2 和 4 bytes，想法和 RISC-V 的 C 擴充接近；AArch64 設計時刻意拿掉它，換取解碼簡單。
    • 
      
  • RISC-V 預留了 48 位元或更長的編碼（最低 5 bits 是 11111），目前沒有標準擴充使用。
    • 
      
  • 變長指令會跨越快取行和 fetch 區塊，第二半要等下一次抓取；RISC-V 開 C 擴充後 4 byte 指令也可能落在 2 byte 對齊的位置。這裡假設每條都抓得完整。
