ISA 比較：x86、ARM、RISC-V

三個指令集架構，在每一個設計決定上各自選了什麼、換到了什麼。每篇挑一個決定，獨立成文，不用照順序讀。

三個 ISA 是誰

指令集架構（ISA）是硬體和軟體之間的契約：有哪些指令、幾個暫存器、怎麼編碼、記憶體怎麼存取。編譯器照契約產出機器碼，CPU 照契約執行。目前通用 CPU 市場的三大宗，各自代表一種設計路線：

系列中用的版本路線誰在用來歷
x86-64CISC，變長編碼，向下相容 1978 年的 8086桌機、筆電、伺服器（Intel、AMD）AMD 2003 年把 32 位元 x86 擴成 64 位元
AArch64RISC，定長 4 bytes，2011 年重新設計的 64 位元 ARM手機、Apple Silicon、嵌入式、雲端伺服器ARM 授權設計給晶片廠，自己不做晶片
RV64GCRISC，開放規格，模組化擴充，4 或 2 bytesMCU、嵌入式、AI 加速器的控制核心，高效能通用市場起步中2010 年 Berkeley 的研究計畫，現由 RISC-V International 維護

全系列固定比較這三個版本：x86 只看 64 位元，ARM 只看 AArch64（不含 32 位元和 Thumb），RISC-V 用 64 位元加上最常見的 G 和 C 擴充。範例都是幾行 C，用 clang 編成三邊的機器碼。

  • 指令編碼：定長與變長

    把同一段 C 編出來的機器碼一次一個 byte 餵給三個解碼器，看誰什麼時候才知道「這條指令有多長」，以及這個差別換到了什麼。

  • 暫存器：16、31、32 個

    一段 C 的變數一個個分配進暫存器，看 x86 什麼時候開始把東西擠到堆疊上。

  • 函式呼叫慣例

    一次 call 的每一步：參數放哪、哪些暫存器要先存、回傳位址在堆疊還是 link register。

  • 條件分支：flags 與比較跳轉合一

    一個 if (a < b) 逐指令執行，看 flags 暫存器怎麼被設又被讀，RISC-V 為什麼省掉這一步。

  • 記憶體定址模式

    一個 a[i].y 的存取，x86 一條 base + index×scale + disp 做完，RISC-V 要幾條。位址算式隨每條指令逐步折疊。

  • 大常數與立即值

    輸入任何一個 64 位元常數，看三邊各要幾條指令才能把它放進暫存器、每條的立即值欄位塞了什麼。

  • CISC 的 micro-op 解碼

    x86 一條複雜指令進前端，看它被拆成幾個 µop，對照 RISC-V 本來就是那幾條。
