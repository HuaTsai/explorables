定址模式 一條指令能算多複雜的位址

每一次記憶體存取都要先算位址：陣列是「起點加索引乘大小」，結構成員是「起點加偏移」。這段算術可以塞進 load 指令本身，也可以用一般算術指令算完再 load。三個 ISA 在這裡劃的線不一樣。按「下一步」看位址算式被每條指令折掉哪一塊。

load 指令能接受的位址寫法

所謂定址模式，就是 load/store 指令的位址欄位允許寫成什麼樣子。允許的形式越多，常見的位址算術就越能在一條指令裡做完；形式越少，就要靠前面的算術指令先把位址算進暫存器。下表是三個 ISA 的清單，base、index 都是暫存器，disp、imm 是寫死在指令裡的常數。

ISA位址可以寫成縮放（index 乘的倍數）常數位移其他
x86-64[base + index×scale + disp]，四項都可省略1、2、4、8 自選，和存取大小無關8 或 32 位元有號[rip + disp32] 相對目前指令位址
AArch64[Rn, #imm]
[Rn, Rm, LSL #s]		只能是 0 或 log2(存取大小)：載入 8 bytes 只能乘 8 或不乘12 位元無號且預先乘上存取大小，或 9 位元有號pre-index [Rn, #imm]! 和 post-index [Rn], #imm 會順便更新 Rn；adrp 取 4 KB 頁位址
RISC-Vimm(rs1)，只有這一種沒有，要自己 slli12 位元有號沒有相對 PC 的 load，要先 auipc 或 lui 算進暫存器

結語

    
定址模式是把常見的位址算術塞進 load 和 store：陣列索引和結構成員最常見，所以「base + index × 大小 + 常數」這個形狀被 x86 直接內建成一條指令的位址欄位。三個 ISA 剛好是三種哲學：x86 最寬，連縮放倍數都可以和存取大小無關；AArch64 給縮放和位移，但縮放綁死在存取大小；RISC-V 只留 base + 12 位元常數，其餘交給 slli、add 這類一般指令。代價差在指令數，不在 bytes：RISC-V 多出來的算術指令壓縮後常是 2 bytes，程式大小和 x86 差不多，真正的差異是同一件事要發出更多條指令，前端要更寬。這也是 RISC-V 後來加 Zba 擴充把縮放加法補回來的原因。

    
位址算式裡的常數部分能放多大，和立即值那一篇是同一個問題：12 bits 的位移放不下就得先湊常數。x86 那個很寬的位址欄位在編碼上要付 ModRM 和 SIB 兩個 byte，見指令編碼；而帶縮放的 load 進了核心可能被拆成兩個 µop，見 micro-op。

    
案例裡沒有迴圈，也假設程式不是位置無關碼，所以有幾件事看不到：

    
    
      
  • pre/post-index 在迴圈裡的價值。AArch64 的 ldr x0, [x1], #8 載入之後順便把 x1 往前推 8，迴圈裡每輪省一條 add；x86 和 RISC-V 都沒有這種會改 base 的 load。
    • 
      
  • x86 的 lea 把定址模式當算術用：lea rax, [rdi + rsi*8 + 16] 只算位址不碰記憶體，等於一條免費的三運算元乘加。
    • 
      
  • segment 暫存器。64 位元下只剩 fs 和 gs 在用，拿來放 thread-local 資料的起點。
    • 
      
  • RISC-V 的 Zba 擴充：sh1add、sh2add、sh3add 一條做 rd = rs1×2/4/8 + rs2。用 -march=rv64gc_zba 重編第一個案例，slli + add 併成 sh3add，三條變兩條；但第三個案例的 ×16 不在 2、4、8 之內，還是三條。RVA22 以後的 profile 已把 Zba 列為必備。
    • 
      
  • 位置無關碼下的全域變數。編成共享函式庫時，g 可能被別的函式庫定義，三邊都要多一次間接：x86 經 g@GOTPCREL，AArch64 的 adrp 改指向 GOT，RISC-V 用 auipc 配 %got_pcrel_hi 再多一條 ld。
    • 
      
  • RISC-V 的 code model。本頁用預設的 medlow，lui 給絕對位址的高 20 位元，程式必須落在 ±2 GB 內；-mcmodel=medany 會改用 auipc 相對 PC，和 AArch64 的 adrp 思路一樣。
