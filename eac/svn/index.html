SVN 超區域值編號：讓 hash 表沿著 EBB 往下傳

LVN 的 hash 表在每個 block 開頭都是空的，所以 B0 算過的 a + b 到 B3 又得重算。Engineering a Compiler 第八章的 superlocal value numbering（SVN）把範圍放大到 extended basic block：只有一個前驅的 block 可以直接接著前驅的表往下算，用 scoped hash table 沿著路徑傳下去、回頭時整張丟掉。這一頁用書上的 CFG 一步步跑給你看，也可以自己改 block 和邊。

LVN 的表在 block 邊界歸零

拿書上的例子，七個 block 的程式碼如下，名字都是 SSA 形式（每個名字只定義一次，後面會講為什麼要這樣）。B0 算了 a0 + b0，B3 的 q0 又算一次。a0、b0 中間沒被改過，所以 q0 是多餘的。LVN 抓不到：它一次只看一個 block，進 B3 的時候表是空的，B0 發過的值編號全忘了。

    → B2

什麼時候可以不忘？如果 B 只有一個前驅 P，那每次執行到 B 都是剛從 P 過來，P 的表裡每一條「這個 key 的值放在名字 x 裡」在 B 的開頭都還成立，B 可以接著 P 的表往下算。如果 B 有兩個以上的前驅，執行到 B 時不知道是從哪一邊來的，哪一邊的表都不能信，只能從空表開始。SVN 整個就是這一個觀察，剩下的是把它做得有效率。

Extended basic block

把「只有一個前驅就能繼承」沿著邊一路往下推，得到的區域叫 extended basic block（EBB）。

CFG 中的 block 集合 S，連同 S 裡指定的一個入口 B1，滿足兩個條件時是一個 EBB：

  1. S 裡除了 B1 以外的每個 block 都恰好有一個前驅，而且那個前驅屬於 S。
  2. S 是極大的：不存在真包含 S 的集合 S′，對某個入口 B1′ 也滿足條件 1。S′ 的入口可以和 S 的不同。

只含一個 block 的 EBB 叫 trivial EBB，含兩個以上的叫 nontrivial EBB。

條件 1 說每個非入口的 block 都只能從集合裡面的一個 block 進來，所以 S 在 CFG 裡的形狀是一棵以 B1 為根的樹，從根到任何一個 block 的路徑上沒有別的入口匯進來。條件 2 是為了讓 EBB 唯一：沒有極大性的話，任何一個 block 自己、任何一棵子樹都算 EBB，「trivial」就沒有意義了。書的邊欄定義只寫「a set of blocks」沒寫 maximal，但正文數出 Figure 8-12 有三個 EBB，只有取極大集合才數得出三個；Cooper 自己的課程投影片則明寫 maximal set，並把單一 block 的 EBB 叫 degenerate EBB。從極大性可以推出兩件判斷用的事：

  • 一個 block 是 EBB 的入口，若且唯若它是 CFG 的入口或有兩個以上的前驅。只有一個前驅的 block 會被那個前驅收進同一個 EBB，自己當入口就不極大。
  • 以 B 為入口的 EBB 是 trivial，若且唯若 B 的每個後繼都有兩個以上的前驅，或 B 沒有後繼。只要有一個後繼只有 B 這一個前驅，它就非收進來不可。

套到上面的 CFG：B1、B3、B4、B6 各只有一個前驅，都被收進 B0 的樹，所以 {B0, B1, B3, B4, B6} 是一個 nontrivial EBB，裡面有三條路徑 ⟨B0, B1⟩、⟨B0, B3, B4⟩、⟨B0, B3, B6⟩。B5 和 B2 各有兩個前驅，是 join point，各自成為 trivial EBB。在 trivial EBB 上沒有表可以繼承，SVN 退化成 LVN。「superlocal」這個詞指的就是這個範圍：比一個 block 大，比整個 CFG 小，剛好是一個 EBB。

每條路徑都像一個 block，但前綴要重用

EBB 裡從入口到某個 block 的每條路徑，執行起來就像一段直線程式碼：⟨B0, B3, B4⟩ 可以看成 m0、n0、q0、r1、e0、s0、u0 七條運算接在一起，對它跑 LVN 就能抓到 q0 和 s0 重複。最笨的做法是對每條路徑各跑一次 LVN，但路徑會共用前綴：B0 會被分析三次，B3 兩次。要重用前綴的分析結果，處理完 ⟨B0, B3, B4⟩ 之後得有辦法把表恢復到 ⟨B0, B3⟩ 末端的狀態，再接著處理 B6。書上列了三種做法：

  • 在每個 block 的邊界把表的狀態記下來，需要的時候恢復。
  • 反向走一遍路徑，把正向走的時候做的改動一條一條撤銷。
  • 用一串接在一起的 hash 表（scoped hash table）當值表。進入一個 block 時開一張新表接在前驅的表外面，要撤銷這個 block 的影響，把它那張表刪掉就好。這就是書上 4.5.1 節符號表的結構：進入一個語法作用域開一張表，查名字由內往外找。編譯器前端通常已經有一份實作。

三種都可行，書上選第三種：最簡單、最快，而且前端的符號表通常已經有這個實作可以直接拿來用。每張表的大小可以照 block 的大小估。

虛擬碼

書上把演算法寫成一個 worklist 迴圈加一個遞迴的 SVN 程序。這裡假設 LVN 已經改成在一串表上工作：查名字、查 key 都從最內層的表往外找，新的 entry 寫進最內層。LVN 的其他部分完全不變。

// Start the process
WorkList ← { entry block }
Empty ← new table for Block
while (WorkList is not empty) do
  remove Block from WorkList
  SVN(Block, Empty)
free Empty

WorkList 裡放的是每個 EBB 的入口。Empty 是一張永遠空著的表，當作每個 EBB 最外層的作用域。「Empty ← new table for Block」是書上原文，這一行其實不屬於任何 block，只是開一張空表讓每個 EBB 入口有外層可以接。

// Superlocal value numbering algorithm
SVN(Block, Table)
  t ← new table for Block
  link Table as the surrounding scope for t
  LVN(Block, t)
  for each successor s of Block do
    if |preds(s)| = 1 then
      SVN(s, t)
    else if s has not been processed then
      add s to WorkList
  free t

只有一個前驅的後繼帶著 t 遞迴下去；其他後繼是新 EBB 的入口，丟進 WorkList。

  • 遞迴就是在走 EBB 這棵樹。任何時刻活著的那串表，由內到外就是從目前的 block 回到 EBB 入口的路徑。SVN(B4, t) 回來的時候 B4 的表已經 free 掉，接下來 SVN(B6, t) 拿到的 t 正好是 ⟨B0, B3⟩ 末端的狀態，這就是上一節要的「恢復」。
  • |preds(s)| = 1 的判斷在說「s 和我同一個 EBB」。s 只有一個前驅，而且那個前驅就是現在的 Block，所以執行到 s 時 t 裡的每一條都還成立。有兩個以上前驅的 s 是另一個 EBB 的入口，它的表要從 Empty 開始。
  • WorkList 是集合，每個 block 只處理一次。B5 會被 B4 和 B6 各看到一次，「s has not been processed」擋掉第二次。取出的順序書上沒規定，這一頁先進先出。從入口到不了的 block 永遠不會進 WorkList，SVN 不會處理它。
  • free t 等於撤銷這個 block 的所有影響。這句話成立的前提是 block 的影響全部寫在 t 裡面，下一節講它什麼時候不成立。

名字只能定義一次，否則表會漏

    
LVN 的虛擬碼寫「if Ti has no table entry then create a table entry」，然後「store k's value number in the table entry for Ti」。放到一串表上，Ti 的 entry 是在 EBB 裡第一次定義它的那個 block 的表裡建的，之後再定義 Ti，找到的是那個舊 entry，新值編號直接寫進去。假設 x 在 B0、B4、B6 都有定義：B0 建了 x 的 entry，B4 重新定義 x 時把新值編號寫進 B0 的表，然後 B4 的表被 free，B0 的表裡 x 的值編號還是 B4 寫的那個。接著處理 B6，它讀到的 x 是 B4 的值，但執行到 B6 根本不會經過 B4。free t 沒有撤銷乾淨，表漏了。

    
書上的解法是在 SSA 形式上跑 SVN。SSA 保證每個名字只在一個地方定義，所以名字的 entry 一定建在定義它的那個 block 的表裡，不會有「第二次定義寫進別人的表」這回事，free 掉定義它的那張表就等於把它的影響全部收回。同時 SSA 也解掉 LVN 那一頁講的 naming 問題：key 底下記的名字永遠不會被覆寫。範例「非 SSA 名字」會跑出一條錯的改寫，「改成 SSA 名字」是同一段程式用 SSA 名字重寫，錯誤就消失了。另一個書上沒走的修法是讓重新定義永遠寫進最內層的表，像符號表處理同名變數那樣遮蔽外層。但那會讓「key 底下的名字還有不有效」更難判斷，不如直接用 SSA。

  


  

    
書上的例子跑出什麼

    
跑完「書上的例子」，五條運算被改寫。Cooper 的課程投影片用同一張 CFG，但 block 標成 A 到 G，對應是 A=B0、B=B1、C=B3、D=B4、E=B6、F=B5、G=B2。B0 的 n0 和 B1 的 r0 是同一個 block 內的重複，LVN 本來就抓得到。另外三條是 SVN 多抓到的：B3 的 q0 和 B4 的 s0 命中 B0 表裡的 m0，B6 的 t0 命中 B3 表裡的 r1。注意 c0、d0 這些從 EBB 外面進來的值，是在第一次遇到它們的 block 的表裡發編號的，所以 B1 和 B3 各發了一套；不同路徑之間本來就不會互相比，所以沒有影響。

    
B5 和 B2 什麼都沒抓到。v0 ← a0 + b0 其實在進 B5 的每一條路徑上都算過了（B4 的 s0、B6 的 e1 之前的 q0，往上追都是 B0 的 m0），但 B5 是 join point，從空表開始，看不到。這是 SVN 的邊界：它只用「唯一前驅」這個最保守的條件，不去問「所有前驅是不是都經過同一個地方」。

  


  

    
結語

    
EBB 是 CFG 裡「只能從根進來」的一棵樹，樹上每條路徑執行起來都像一條 block。SVN 就是 LVN 加一串 scoped hash table：進入 block 開一張表接在前驅的表外面，離開時整張丟掉，任何時刻活著的那串表正好是從 EBB 入口到目前 block 的路徑。只有一個前驅的後繼帶著表遞迴下去，join point 當作新 EBB 的入口丟進 worklist、從空表開始。「丟掉表就等於撤銷」這件事要靠 SSA 才成立，名字能重複定義的話，新值會寫進別人的表，free 不乾淨。

    
join point 從空表開始是浪費的：B5 的兩個前驅都經過 B3，B3 表裡的東西在 B5 其實都還成立。把「唯一前驅」換成「dominator」，就是書上 8.5.2 節的 dominator-based value numbering，需要先算出第九章的 dominator 樹；再往上是整個 CFG 的 global value numbering。要對整張圖推理而不是沿著路徑走，得換成列方程式解不動點的做法，LiveOut 頁用活躍變數示範。同一章末的復習題問把樹高平衡推到 superlocal 範圍會遇到什麼：沿著 ⟨B0, B3, B4⟩ 做完之後要處理 ⟨B0, B3, B6⟩，B3 裡已經被改寫過的樹要怎麼復原，和這一頁的「前綴要重用」是同一個問題，但樹的改寫比 hash 表難撤銷。

    
這一頁把 φ 的結果當成新值，沒有比較它的參數；WorkList 的取出順序書上沒規定，這裡先進先出；LVN 用的是基本版，沒有交換律、常數摺疊和恆等式，那些在 LVN 頁，接上來的方式一樣。load 和 store、跨 block 之後的死碼刪除，都不在這裡。
