Balance 樹高平衡：把長鏈運算式變成矮樹

前端把 a + b + c + d 翻成三條相依的加法，一條接一條，像一根長鏈。能同時發兩條指令的機器只能乾等。tree-height balancing 利用加法可交換、可結合，把長鏈改排成矮樹，讓獨立的子運算式可以平行算。這一頁把 Engineering a Compiler 第八章的兩階段演算法一步步跑給你看：第一階段找出每棵樹的根，第二階段用 Flatten 把樹攤成葉子佇列、再用 Rebuild 照等級重新配對。原樹和重建樹並排畫出來。

鏈和樹的差別

同一個運算式 a + b + c + d + e + f + g + h，左邊是前端自然產出的形狀，每一條加法都要等前一條；右邊是平衡過的形狀，第一層四條加法彼此獨立。兩種形狀都是 7 次加法，差的是關鍵路徑：7 層對 3 層。

三個觀念

  • 候選樹。只有可交換又可結合的運算子（這一頁支援 + 和 ×）才能重排。減法和除法不行，它們的結果在樹裡只能當葉子。
  • 根。一棵樹能重排到多大，取決於哪些中間值「非算出來不可」。第一階段的判斷是一句話：Opi 可交換可結合，而且 Ti 是暴露值（exposed），就標成根。前提先過濾掉一批：由 −、÷ 算出來的值永遠不是根，不管它暴不暴露，在別棵樹裡只能當葉子。暴露則有三個條件，符合任何一個就算：
    1. 離開 block 時還活著（live on exit）：後面的 block 還要用它，所以它一定要真的算出來、存進那個名字。
    2. 在 block 裡被用超過一次：它是共用的子運算式，攤平進任何一棵樹都會讓它被重算，所以只能算一次、以結果當葉子。
    3. 被用一次，但用它的那條運算的運算子和 Opi 不同：t3 ← a + b 被 t4 ← t3 × c 用到，× 樹不能穿過 + 去重排 a 和 b。「不同」包括另一個可重排的運算子，也包括 −、÷ 這種本來就不能重排的。
    反過來說，不是根的情況只有一種：由可重排運算子算出來、只在 block 內用一次、用它的運算又是同一個運算子。這種值才是 Flatten 會穿過去繼續攤平的中間節點。根是樹和樹之間的邊界，別棵樹看到它只能當葉子。
  • 葉子從哪裡來。Flatten 碰到的名字有三種來源。常數。Upward exposed 的名字：在 block 裡被用到時前面還沒有任何運算定義它，值是從 block 外面帶進來的；這就是書上 UEVar（upward-exposed variable）的意思，大例子裡的 a、b、c 都是。它不是這個 block 算的，Flatten 沒有東西可以往下走，只能當葉子。別棵樹的根：這個 block 算的但不能省掉，Flatten 走到它就要停。注意 upward exposed 和 live on exit 是兩個不同的概念，一個看入口、一個看出口：前者只看 block 自己的程式碼就能判斷，後者要看 block 之後的路徑，是 live variable analysis 跨 block 算出來的，所以 workbench 要你另外填 live 集合。一個名字可以兩者都是（從外面進來又在後面被用）、也可以都不是（block 算的、只在 block 內用）。
  • 等級。Flatten 給每片葉子一個等級（rank）：常數 0、外面來的名字 1、別棵樹的根是它自己的等級。內部節點的等級是兩個子節點相加，差不多就是子樹的葉子數。Rebuild 每次從佇列拿等級最小的兩個配對，和 Huffman 編碼一樣的手法，矮的子樹先合，樹自然平衡。

虛擬碼

照書上的寫法。Roots 和 q 都是優先佇列：Roots 按運算子優先級由低到高出列，q 按等級由低到高出列。書上沒有明說同等級時誰先；這一頁用後進先出，因為這樣能重現書上 Roots 的順序和大多數圖例。

// Phase 1: build a queue, Roots, of the candidate trees
Roots ← new empty queue
for i ← 0 to n − 1 do
  Rank(Ti) ← −1
  if Opi is commutative and associative
      and Ti is exposed then
    mark Ti as a root
    Enqueue(Roots, Ti, precedence of Opi)

// Phase 2: remove a tree from Roots and rebalance it
while (Roots is not empty) do
  var ← Dequeue(Roots)
  Balance(var)

Balance(root)
  if Rank(root) ≥ 0 then return   // already processed
  q ← new empty queue
  Rank(root) ← Flatten(Li, q) + Flatten(Ri, q)
  Rebuild(root, q, Opi)

Balance 的第一行讓同一棵樹只處理一次：不管是從 Roots 拿到，還是別棵樹的 Flatten 遞迴碰到。

Flatten(node, q)
  if node is a constant then
    Rank(node) ← 0; Enqueue(q, node, Rank(node))
  else if node is upward exposed then
    Rank(node) ← 1; Enqueue(q, node, Rank(node))
  else if node is a root then
    Balance(node); Enqueue(q, node, Rank(node))
  else   // interior node for Tj ← Lj Opj Rj
    Rank(node) ← Flatten(Lj, q) + Flatten(Rj, q)
  return Rank(node)

Rebuild(root, q, op)
  while (q is not empty) do
    NewL ← Dequeue(q); NewR ← Dequeue(q)
    if NewL and NewR are both constants then
      NewT ← Fold(op, NewL, NewR)
      if q is empty then
        create the op "root ← NewT"; Rank(root) ← 0
      else
        Enqueue(q, NewT, 0); Rank(NewT) ← 0
    else
      if q is empty then NewT ← root
      else NewT ← new name
      create the op "NewT ← NewL op NewR"
      Rank(NewT) ← Rank(NewL) + Rank(NewR)
      if q is not empty then Enqueue(q, NewT, Rank(NewT))

Flatten 只把葉子放進 q，內部節點只算等級。Rebuild 每一圈從 q 取兩個、放回一個，q 每圈少一個，剛好在剩兩個時收尾成 root。

根、等級、配對：三個決定的理由

    
    
      
  • 「被用超過一次」為什麼要當根。如果 t3 被兩棵樹用到，又讓兩棵樹各自把它攤平，t3 的加法會被算兩次。當成根就只算一次，兩棵樹拿現成的值。代價是 t3 的子樹不能和外面的葉子混著重排。
    • 
      
  • Roots 為什麼按優先級由低到高。大例子裡 t11（加法）先處理，Flatten 碰到 t3、t7 時順手把它們也平衡了；後來 Roots 再拿到 t3、t7，Balance 第一行直接返回。順序其實不影響正確性，遞迴保證子樹先完成，但低優先級先做能讓最後的輸出順序比較自然。
    • 
      
  • Flatten 回傳的等級不是高度。它是葉子等級的總和，常數算 0，所以一棵全是常數的子樹等級是 0，會被最先配對、最先摺疊掉。這就是 Balance 順便做常數聚集的原因：大例子裡 13 和 4 隔著兩層，照樣被湊在一起變成 17。
    • 
      
  • Rebuild 的常數分支。兩個常數配對後不產生運算，只把摺疊結果以等級 0 放回 q。只有 q 剛好空了才會寫出 root ← 常數。
    • 
      
  • 減法和除法的結果當葉子。虛擬碼只說 upward exposed 的名字當葉子，但一個由 − 算出來、只被用一次的名字既不是根也不能攤平。這一頁把它當等級 1 的葉子，原來的減法照樣留在輸出裡。
    • 
      
  • 按等級貪婪配對不保證最矮。大例子裡 t6 那棵原本高度 3，重建後還是 3，書上的圖 8-11 也是如此。因為 t3 的等級是 2，比 u、v 大，演算法先把 3、u、v 湊在一起，最後才和 t3 合，結果是一條鏈。手動配成 (3 × u) × (v × t3) 可以到高度 2。等級是葉子數的近似，不是高度。
    • 
      
  • 每個名字只定義一次。這一頁要求輸入是 SSA 式的。書上的例子也是如此，演算法本身沒有處理重新賦值。

書上的圖和虛擬碼對不起來的地方

    
    
      
  • 小例子裡 t2 的等級。書上說 Rebuild 收到 n 的四個運算元時「每個等級都是 1」。但照 Flatten 的寫法，t2 是另一棵樹的根，先呼叫 Balance(t2)，回來的等級是 3（葉子 a、b、c）。照虛擬碼跑，Rebuild 會先把 e、f 配對，再配 g，最後才和 t2 合，和書上畫的 (t2 × e) × (f × g) 不同。這一頁照虛擬碼跑，兩種結果高度一樣。
    • 
      
  • 同等級的出列順序。書上沒有明說。這一頁用後進先出，能重現書上的 Roots 順序、t3、t7、t10 的全部新運算，以及 t11 的配對方式。剩下的差異只有運算元左右對調：t6 那棵書上先配 v 這裡先配 u，t11 最後一條書上寫 n2 + t3 這裡是 t3 + n2。書上 t6 那棵其實是先進先出，兩種順序書上自己也混著用。

結語

    
先決定哪些值非算不可，再在這些值之間自由重排：根是邊界，Flatten 攤到根就停。等級小的先配對，樹就平衡，常數也順便湊在一起，和 Huffman 編碼是同一個直覺。平衡不是免費的，矮樹同時活著的中間值比長鏈多，暫存器壓力上升，在真實編譯器裡這個 pass 要和排程器、配置器一起看。LLVM 的 Reassociate pass 做的就是這件事，也用等級。

    
這個 pass 把長鏈變矮，是為了給指令排程更多可以並行的機會，書上第十二章的 list scheduling 就是吃這種樹；它製造的暫存器壓力則由第十三章的暫存器配置承受。同一章的 區域值編號是另一種 block 內的變換，兩者都假設每個名字只定義一次，從線性 IR 切出 block 的方法在 CFG 那一頁。

    
浮點加法不滿足結合律，這個變換會改變結果，編譯器只在 fast-math 之類的旗標下對浮點做這件事。常數摺疊照 JavaScript 的整數算，真的編譯器要照目標機器的位寬和溢位語意。&、|、^ 也是可交換運算子，這裡只做 + 和 ×。既沒人用又不活著的候選運算不會成為根，這一頁原樣保留在輸出裡，真的編譯器會把它刪掉。書上提醒平衡後的樹會增加同時活著的值，這一頁不計算這件事。
