LVN 區域值編號：在一個 block 裡找重複的計算

一個 basic block 裡常常有同一個值被算了兩次。要找出來，比對「運算式長得一不一樣」是不夠的：名字會被覆寫，b + c 出現兩次不代表是同一個值。Engineering a Compiler 第八章的 local value numbering（LVN）改成追蹤「值」：每個值一個編號，用編號組 hash key 查重複。這一頁把書上的虛擬碼一步步跑給你看，可以在基本版和擴展版之間切換，也可以自己改程式碼。

名字和值是兩回事

看這段程式。第 4 條的 a − d 和第 2 條一模一樣，而且 a、d 中間都沒被改過，所以第 4 條是多餘的。第 3 條的 b + c 也和第 1 條長得一樣，但 b 在第 2 條被覆寫了，算出來是不同的值。

a ← b + c
b ← a − d
c ← b + c
d ← a − d

LVN 的做法是給每個「值」一個值編號（value number）。名字只是值暫時放的位置，名字被重新賦值，就換成裝新的值編號。要判斷兩個運算是不是算同一個值，看的是「運算子加上兩個運算元的值編號」，這三樣東西組成 hash key。key 相同，值就相同。

兩張表就夠了：一張把名字對到值編號，一張把 key 對到值編號（和一個可以去拿這個值的名字）。演算法從頭到尾掃一遍 block，每條運算查一次表。

兩個版本的虛擬碼

左邊是基本版。右邊是擴展版，綠色的行是多出來的：先把可交換運算的兩個值編號排成固定順序，命中 key 時允許直接寫常數，新 key 的時候順手做常數摺疊和代數恆等式化簡。核心迴圈完全沒變。

for i ← 1 to n, where the block has n operations
    in the form "Ti ← Li Opi Ri" do
  get the value numbers V1 and V2 for Li and Ri
  if Ti has no table entry then
    create a table entry for Ti
  construct a hash key, k, as ⟨V1, Opi, V2⟩
  if k is already present in the table then
    replace operation i with "Ti ← x",
        where x is the name stored under the key k
  else
    create a table entry for k
    generate a new value number for k
        and store it in k's table entry
    store the name Ti in k's table entry
  store k's value number in the table entry for Ti

最後一行在 if/else 外面：不管 key 是舊的還是新的，Ti 都拿到 k 的值編號。

for i ← 1 to n, where the block has n operations
    in the form "Ti ← Li Opi Ri" do
  get the value numbers V1 and V2 for Li and Ri
  if Ti has no table entry then
    create a table entry for Ti
  if Opi commutes and V1 > V2 then
    swap V1 and V2
  construct a hash key, k, as ⟨V1, Opi, V2⟩
  if k is already present in the table then
    replace operation i with "Ti ← x",
        where x is the constant value or name stored under the key k
  else
    create a table entry for k
    generate a new value number for k
        and store it in k's table entry
    store the name Ti in k's table entry
    if V1 and V2 are both marked as constant then
      evaluate Li Opi Ri into c
      replace operation i with "Ti ← c"
      store c in the table entries for k and Ti
    else if Li Opi Ri matches an algebraic identity then
      replace operation i with the simplified version
  store k's value number in the table entry for Ti

交換律的處理在組 key 之前；常數摺疊和恆等式只在「新 key」的分支裡，因為 key 命中時表裡已經有答案了。

值編號什麼時候取、什麼時候給

    
    
      
  • 運算元的值編號在覆寫 Ti 之前就取好了。所以 a ← a + b 沒問題：右邊的 a 拿到的是舊值編號，最後一行才把 a 換成新的。「if Ti has no table entry」那兩行只是確保最後一行有地方可以寫。
    • 
      
  • 第一次出現的名字當場發新編號。虛擬碼寫「get the value numbers」沒說找不到怎麼辦，書上正文有補：沒有值編號的名字就給一個新的。這代表「從 block 外面進來的值」，每個都當成彼此不同。
    • 
      
  • key 裡沒有名字。⟨V1, Op, V2⟩ 三樣都和名字無關，所以名字被覆寫不會讓 key 失效，只會讓 key 底下存的那個名字失效。這是下一節的重點。
    • 
      
  • 交換律比的是值編號的大小，不是名字。V1 > V2 就交換，讓 x + y 和 y + x 做出同一個 key。減法和除法不可交換，順序要保留。
    • 
      
  • 常數摺疊只在新 key 的分支裡。如果 key 命中，表裡早就存著常數，直接照抄。摺疊完要把常數同時記在 key 和 Ti 的 entry 上，後面用到 Ti 的運算才能繼續摺疊。
    • 
      
  • 恆等式化簡之後，Ti 拿到的仍是 key 的新值編號。照虛擬碼，a ← x + 0 改寫成 a ← x，但 a 的值編號是 ⟨Vx, +, V0⟩ 的新編號，不是 x 的。於是之後 a + y 和 x + y 做出不同的 key，重複沒被抓到。「化簡後的值編號」那個範例就是這個情況。更細心的實作會讓 a 直接拿 x 的值編號。

naming 問題：hash 表裡的名字會過期

    
命中 key 的時候，演算法把運算改寫成 Ti ← x，x 是當初第一次算出這個值時的目標名字。但那個名字之後可能被重新賦值了。「naming 問題」這個範例：


a ← x + y      ⟨Vx, +, Vy⟩ 是新 key，記下名字 a
b ← x + y      命中，改寫成 b ← a   ✓
a ← 17         a 的值編號換掉了，但 key 底下還記著名字 a
c ← x + y      命中，改寫成 c ← a   ✗  a 現在是 17

    
值的判斷沒有錯：第 4 條算的確實還是第 1 條那個值。錯的是「去哪裡拿」。這一頁照虛擬碼執行，遇到這種情況會把改寫標成紫色並說明。書上給兩種修法：

    
    
      
  • 改寫前檢查名字還有效。x 目前的值編號必須等於 key 的值編號；不等就代表 x 被覆寫了，要找其他還裝著這個值的名字（上例中的 b），找不到就老實重算。實作上可以替每個值編號維護「目前哪些名字裝著它」的清單。
    • 
      
  • 改用 SSA 命名。每個名字只定義一次，第 3 條變成 a1 ← 17，a0 永遠裝著 x + y，c ← a0 一定正確。這是後面章節幾乎所有最佳化都建在 SSA 上的原因之一。
    • 
    

  


  

    
結語

    
值編號回答「這算出來是哪個值」，名字只回答「它暫時放在哪」；名字被覆寫就換編號，所以長得一樣的運算式不一定是同一個值，長得不一樣的也可能是。key 由值編號組成，所以不會過期，會過期的是 key 底下記的名字，改寫成 T ← x 之前要確認 x 還裝著那個值，或一開始就用 SSA 名字。擴展版的功能都插在固定的兩個位置：組 key 之前整理 key，建新 key 的時候順手算，核心迴圈還是「查表、沒有就新增、把編號給 T」。

    
LVN 只看一個 block，表在 block 開頭是空的。書上第八章接著把它推到 extended basic block 和整個 CFG（superlocal 和 global value numbering），表要能沿著 CFG 的路徑繼承和回收，那需要先有 CFG。同一章的 樹高平衡是另一種 block 內的變換，和 LVN 一樣靠「每個名字只定義一次」才好做。

    
這一頁只有暫存器之間的算術，load 和 store 要考慮位址是否相同、中間有沒有別的 store，書上在後面才處理。改寫成 T ← x 之後如果 T 沒人用，整條可以刪掉，那是另一個 pass 的事。恆等式書上列了二十幾條，這裡只做加減乘除最常見的幾條，a ÷ a = 1 假設 a ≠ 0。常數摺疊照 JavaScript 的整數運算做，除法向零截斷，除以零不摺疊，真的編譯器要照目標機器的語意。naming 問題這裡只標出錯誤，沒有實作「找別的有效名字」或 SSA 改名。
