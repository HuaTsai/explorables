Heap 與 heapsort：一個陣列怎麼假裝成一棵樹

Heap 是一個普通的陣列，只是我們用「第 i 格的小孩在第 2i 和 2i + 1 格」這條規則把它讀成一棵幾乎填滿的二元樹，再要求每個父節點都不小於小孩。Introduction to Algorithms 第六章用它做兩件事：原地排序，和一個每次都能在 O(lg n) 內拿出最大值的 priority queue。這一頁把書上的虛擬碼一步步跑給你看，陣列和樹並排，可以自己改輸入。

陣列裡藏著一棵樹

書上的陣列從 1 開始編號。A[1] 是根，第 i 格的左小孩在 2i，右小孩在 2i + 1，父節點在 ⌊i/2⌋。這三個運算在二進位裡就是左移、左移加一、右移，所以「找父子」不用存任何指標。這樣讀出來的樹一定是完全二元樹：每一層都填滿，只有最底層可能缺右邊幾個。

PARENT(i)
    return ⌊i/2⌋
LEFT(i)
    return 2i
RIGHT(i)
    return 2i + 1

第 i 格是不是葉子，看 2i 有沒有超過 heap-size 就知道。n 個元素的 heap，葉子正好是第 ⌊n/2⌋ + 1 到 n 格，高度是 ⌊lg n⌋。

圖 6.1 的 heap：陣列 16 14 10 8 7 9 3 2 4 1，每個節點下面的小字是它在陣列裡的位置。

Max-heap property：除了根以外，每個節點都滿足 A[PARENT(i)] ≥ A[i]。這條規則只管父子，不管兄弟，所以左小孩不一定比右小孩大。它的直接推論是：任何子樹的根都是那棵子樹裡最大的值，特別是 A[1] 永遠是全場最大。

陣列有兩個長度。A.length 是陣列本身的格數，A.heap-size 是前面多少格算在 heap 裡。後面會看到 heapsort 靠的就是這兩個數字分開：heap 一格一格縮小，縮掉的那一格留給排好的最大值。

三段虛擬碼，一個核心動作

整章只有一個真正的動作：MAX-HEAPIFY 把一個「可能比小孩小」的節點沉到該去的位置。前提是它的兩棵子樹已經各自是 max-heap，所以只要沿著一條路徑往下修就好：每一層看三個值，挑最大的，只往被換下去的那一邊走，不回頭檢查另一邊。時間是 O(h) = O(lg n)。前提不成立的話結果就不保證是 heap，「單次 MAX-HEAPIFY」模式會提醒你。建 heap 和排序都是在不同地方呼叫它。

證明：MAX-HEAPIFY 是 O(lg n)

設 T(n) 是對一棵 n 個節點的子樹呼叫 MAX-HEAPIFY 的時間。除了遞迴呼叫以外的工作是 Θ(1)，遞迴只會進入其中一棵子樹，所以要問的是：子樹最大能有多大？

最壞的情況是最底層剛好填滿一半：左子樹比右子樹多一整層。設樹高 h，左子樹是高 h − 1 的滿樹，有 2h − 1 個節點；右子樹是高 h − 2 的滿樹，有 2h−1 − 1 個；全部 n = 3 · 2h−1 − 1。左子樹佔 (2h − 1)/(3 · 2h−1 − 1)，h 越大越接近 2/3，而且永遠不超過 2/3。所以 T(n) ≤ T(2n/3) + Θ(1)，套 master theorem 的第二種情況（a = 1、b = 3/2、f(n) = Θ(1) = Θ(nlogb a)）得到 T(n) = O(lg n)。用高度說就是 O(h)。

MAX-HEAPIFY(A, i)
 1  l = LEFT(i)
 2  r = RIGHT(i)
 3  if l ≤ A.heap-size and A[l] > A[i]
 4      largest = l
 5  else largest = i
 6  if r ≤ A.heap-size and A[r] > A[largest]
 7      largest = r
 8  if largest ≠ i
 9      exchange A[i] with A[largest]
10      MAX-HEAPIFY(A, largest)

第 3 到 7 行在 i、l、r 三個裡挑最大的，超過 heap-size 的小孩不算，比較用的是嚴格大於，相等不交換。第 8 到 10 行：如果最大的不是 i，交換，然後到被換下去的那個位置繼續。最後一行是尾遞迴，習題 6.2-5 要你改成 while 迴圈；workbench 右下的「呼叫」那一行會顯示遞迴永遠只是一條鏈。

BUILD-MAX-HEAP(A)
 1  A.heap-size = A.length
 2  for i = ⌊A.length/2⌋ downto 1
 3      MAX-HEAPIFY(A, i)

從最後一個非葉節點倒著走到根。倒著走是為了滿足 MAX-HEAPIFY 的前提（習題 6.3-2）：處理 i 的時候，它的兩個小孩已經處理過了。第 ⌊n/2⌋ + 1 到 n 格是葉子，對葉子呼叫 MAX-HEAPIFY 什麼都不會發生（習題 6.2-4），所以不用管。

HEAPSORT(A)
 1  BUILD-MAX-HEAP(A)
 2  for i = A.length downto 2
 3      exchange A[1] with A[i]
 4      A.heap-size = A.heap-size − 1
 5      MAX-HEAPIFY(A, 1)

每一輪把最大值換到 heap 的最後一格，把那一格劃出 heap，再修根。n − 1 輪之後整個陣列由小到大，而且沒有多用一格空間：排好的部分就藏在 heap-size 之外。

證明：HEAPSORT 的正確性（習題 6.4-2）

Loop invariant：每一輪開始時，A[1..i] 是一個 max-heap，裝著 A 裡最小的 i 個元素；A[i+1..n] 裝著最大的 n − i 個，而且已經排好。

  1. 初始：BUILD-MAX-HEAP 之後 A[1..n] 是 max-heap，A[n+1..n] 是空的，invariant 成立。
  2. 維持：A[1] 是 A[1..i] 裡最大的，換到 A[i] 之後，A[i..n] 排好而且是最大的 n − i + 1 個。heap-size 減成 i − 1，根可能壞掉，MAX-HEAPIFY(A, 1) 把 A[1..i−1] 修回 max-heap。下一輪的 invariant 成立。
  3. 終止：i = 1 時 A[1] 是最小的，A[2..n] 是排好的最大 n − 1 個，整個陣列排好了。
HEAP-MAXIMUM(A)
 1  return A[1]

HEAP-EXTRACT-MAX(A)
 1  if A.heap-size < 1
 2      error "heap underflow"
 3  max = A[1]
 4  A[1] = A[A.heap-size]
 5  A.heap-size = A.heap-size − 1
 6  MAX-HEAPIFY(A, 1)
 7  return max

HEAP-INCREASE-KEY(A, i, key)
 1  if key < A[i]
 2      error "new key is smaller than current key"
 3  A[i] = key
 4  while i > 1 and A[PARENT(i)] < A[i]
 5      exchange A[i] with A[PARENT(i)]
 6      i = PARENT(i)

MAX-HEAP-INSERT(A, key)
 1  A.heap-size = A.heap-size + 1
 2  A[A.heap-size] = −∞
 3  HEAP-INCREASE-KEY(A, A.heap-size, key)

Priority queue 的四個操作。取最大值和 heapsort 的一輪幾乎一樣：把最後一格搬到根，heap-size 減一，那一格的舊值還留在陣列裡，只是不算在 heap 裡了。把 key 變大是反方向的動作，節點往上浮。插入先在尾端放一個 −∞，這樣一定不違反 max-heap property，再把它「變大」成要插的值，往上浮的程式只要寫一次。

為什麼 BUILD-MAX-HEAP 是 O(n) 而不是 O(n lg n)

    
粗估是 n/2 次呼叫，每次 O(lg n)，所以 O(n lg n)。這個上界沒錯，但不緊。緊的算法是看每個節點的高度：高度 h 的節點最多 ⌈n/2h+1⌉ 個，每個最多沉 h 層，總共

    
Σh=0⌊lg n⌋ ⌈n/2h+1⌉ · O(h) = O(n · Σh h/2h) = O(n)

    
因為 Σ h/2h 收斂到 2。白話說：會沉很深的節點很少，數量多的節點都在底層附近，沉不了幾步。「已排序的輸入」那個範例是最壞情況，每個被處理的節點都沉到底，15 個元素總共只交換 11 次；如果每次都走滿高度 3，7 個非葉節點會交換 21 次。

    
HEAPSORT 沒有這種便宜可以撿：n − 1 次 MAX-HEAPIFY 都是從根開始，而且習題 6.4-3 和 6.4-5 說明不管輸入是什麼順序，都是 Θ(n lg n)。

    

      證明：高度 h 的節點最多 ⌈n/2h+1⌉ 個，以及總和為什麼是 O(n)
      
先看葉子（h = 0）：習題 6.1-7 說葉子是第 ⌊n/2⌋ + 1 到 n 格，共 ⌈n/2⌉ 個。把葉子全部拿掉，剩下的 ⌊n/2⌋ 個節點又是一個 heap，它的葉子就是原來高度 1 的節點，最多 ⌈⌊n/2⌋/2⌉ ≤ ⌈n/4⌉ 個。一直做下去，高度 h 的節點最多 ⌈n/2h+1⌉ 個。

      
每個高度 h 的節點呼叫 MAX-HEAPIFY 花 O(h)，所以總時間是

      
Σh=0⌊lg n⌋ ⌈n/2h+1⌉ · O(h) = O(n · Σh=0∞ h/2h)

      
而 Σ h · xh = x/(1 − x)2，代 x = 1/2 得到 2。所以 BUILD-MAX-HEAP 是 O(n)。

    

  


  

    
結語

    
Heap 是陣列加一條讀法：2i 和 2i + 1 是小孩，⌊i/2⌋ 是父親，不存指標，形狀永遠是完全二元樹。整章只有一個核心動作，把一個節點沉到對的位置，前提是子樹已經好了，所以是 O(lg n)。建 heap 是從中間倒著對每個非葉節點做一次，加起來是 O(n)；排序是對根做 n − 1 次，排好的部分藏在 heap-size 之外，所以是原地的。

    
第七章的 quicksort 是實務上更常贏的 O(n lg n) 排序，第八章證明比較排序的下界就是 Ω(n lg n)，所以 heapsort 和 merge sort 已經是最好的那一類。Priority queue 的用途在圖的章節才真正出現：BFS 用的是普通的 queue，把它換成 min-priority queue 就是 Prim 和 Dijkstra，那時需要的是 DECREASE-KEY，和這一頁的 INCREASE-KEY 方向相反。

    
這一頁只做 max-heap，min-heap 是把所有比較反過來。書上 6.5 節提到實務上 heap 裡存的是物件，INCREASE-KEY 要靠 handle 找到物件現在在哪一格，這裡直接用陣列位置。MAX-HEAP-INSERT 應該檢查 heap-size 會不會超過 A.length，這裡讓陣列直接長一格。真的寫程式時陣列從 0 開始，公式變成小孩在 2i + 1 和 2i + 2、父親在 ⌊(i − 1)/2⌋。Heapsort 不是穩定排序，而且存取模式跳來跳去，對快取不友善，這是它實務上輸給 quicksort 的主要原因。
