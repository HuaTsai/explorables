Kruskal 與 Prim：最小生成樹

把一張有權重的無向圖的頂點全部接起來，而且總成本最低，這就是最小生成樹（minimum spanning tree，MST）。Introduction to Algorithms 第二十三章先給一個通用的 greedy 框架：每一步加一條「安全」的邊，而 cut 和 light edge 告訴你哪些邊是安全的；Kruskal 和 Prim 只是用不同的方式挑 light edge。這一頁把兩個演算法連同 Kruskal 用到的 disjoint set 一步步跑給你看，也可以自己畫 cut，看 light edge 落在哪裡。

問題，和一個通用的框架

給一張連通的無向圖 G = (V, E)，每條邊有權重 w(u, v)，代表把 u 和 v 接起來的成本。要找一個邊的子集合 T ⊆ E，讓所有頂點連通，而且總權重 w(T) = Σ w(u, v) 最小。只要權重都是正的，最省的 T 一定沒有環：有環就能拿掉環上一條邊，還是連通但更便宜（習題 23.1-7；權重可以是 0 或負數時這句話不成立）。所以 T 是一棵樹，剛好 |V| − 1 條邊，叫做 G 的 minimum spanning tree。MST 不一定唯一，權重平手時可能有好幾棵，但每一棵的總權重一樣，連排序後的權重列表都一模一樣（習題 23.1-8）。

書上的兩個演算法是同一個 greedy 骨架的特例。維護一個邊的集合 A，loop invariant 是：每一輪開始前，A 是某棵 MST 的子集合。每一輪找一條加進去之後仍維持這個性質的邊，叫做對 A 的 safe edge，加進 A；做 |V| − 1 輪，A 就是一棵 MST。框架本身的正確性沒什麼好說的：空集合是任何 MST 的子集合；每次只加 safe edge；結束時 A 是某棵 MST 的子集合又已經是一棵 spanning tree，所以就是那棵 MST。真正的問題只有一個：怎麼有效率地認出 safe edge。

GENERIC-MST(G, w)
1  A = ∅
2  while A does not form a spanning tree
3      find an edge (u, v) that is safe for A
4      A = A ∪ {(u, v)}
5  return A

Cut 和 light edge：認出 safe edge 的方法

四個定義：

cut (S, V − S)把 V 分成兩半的一個 partition。
crosses邊 (u, v) 穿過這個 cut：u 和 v 分別在兩邊。
respectscut respect 一個邊集合 A：A 裡沒有任何一條邊穿過這個 cut。
light edge穿過 cut 的邊裡權重最小的那一條；平手時可以有好幾條。

Theorem 23.1：設 A 是某棵 MST 的子集合，(S, V − S) 是任何一個 respect A 的 cut，(u, v) 是穿過這個 cut 的 light edge，那麼 (u, v) 對 A 是 safe 的。直覺是「剪貼」：拿一棵包含 A 的 MST T。T 若已經有 (u, v) 就沒事；否則 T 裡從 u 到 v 的路徑也得跨過這個 cut，路徑上找一條跨過的邊 (x, y)，拿掉它、換成 (u, v)。(u, v) 是 light edge，所以權重只會更小或相等，換出來的 T′ 還是 MST，而且 A 和 (u, v) 都在裡面。關鍵的一句話：把跨過 cut 的另一條邊換成 light edge，只會更好，不會變壞。

證明：Theorem 23.1

設 T 是一棵包含 A 的 MST。若 T 已經包含 (u, v)，A ∪ {(u, v)} ⊆ T，結論成立。否則我們用剪貼法造出另一棵包含 A ∪ {(u, v)} 的 MST T′。

T 是 spanning tree，所以有一條從 u 到 v 的 simple path p，接上 (u, v) 就是一個環。u 和 v 在 cut 的兩側，所以 p 上至少有一條邊也穿過這個 cut，任取一條叫 (x, y)。因為 cut respect A，(x, y) ∉ A。(x, y) 在 T 裡 u 到 v 唯一的 simple path 上，拿掉它 T 會斷成兩個元件，而 u、v 各在一邊，加上 (u, v) 剛好重新接起來，得到新的 spanning tree T′ = T − {(x, y)} ∪ {(u, v)}。

T′ 是 MST：(u, v) 是這個 cut 的 light edge，(x, y) 也穿過這個 cut，所以 w(u, v) ≤ w(x, y)，於是 w(T′) = w(T) − w(x, y) + w(u, v) ≤ w(T)；而 T 是 MST，w(T) ≤ w(T′)，所以 w(T′) = w(T)，T′ 也是 MST。

最後，A ⊆ T 而 (x, y) ∉ A，所以 A ⊆ T′，進而 A ∪ {(u, v)} ⊆ T′。T′ 是 MST，所以 (u, v) 對 A 是 safe 的。

Corollary 23.2 把定理講成演算法好用的形式：把 A 看成一座森林 GA = (V, A)，C 是其中一棵樹（一個連通元件）。若 (u, v) 是連接 C 和別的元件的所有邊裡最輕的，那它是 safe 的。理由是 cut (VC, V − VC) 必然 respect A（A 的每條邊都在自己那棵樹裡面，不會跨出去），而 (u, v) 正是這個 cut 的 light edge。Kruskal 和 Prim 都靠這個推論：Kruskal 每次挑整張圖裡「連接兩個不同元件」的最輕邊，Prim 每次挑「連接目前這一棵樹和外面」的最輕邊。A 裡每加一條邊，森林就少一棵樹，從 |V| 棵做到 1 棵，剛好 |V| − 1 輪。

兩個容易想反的地方。第一，定理的逆敘述不成立：safe edge 不一定是 light edge（習題 23.1-2，workbench 有反例）。第二，把「對某個 cut 是 light edge」的邊全部收集起來，不一定是一棵樹：三角形三邊權重都是 1，每條邊都是某個 cut 的 light edge，但三條邊有環（習題 23.1-4）。但有一個方向成立：MST 裡的每一條邊都是某個 cut 的 light edge，把那條邊從樹上拿掉，樹分成兩半，那就是要的 cut（習題 23.1-3）。進一步，若每個 cut 的 light edge 都唯一，MST 就唯一；反之不然（習題 23.1-6，也有範例）。Workbench 的「Cut 與 light edge」模式可以點頂點自己畫 cut，上面這幾題都做成了範例。

Kruskal：一座森林，照權重從小到大

Kruskal 把 A 當成森林。一開始每個頂點自己是一棵樹；把所有邊照權重從小到大排好，依序看每一條 (u, v)。若 u 和 v 在不同的樹裡，這條邊就是連接這兩棵樹的所有邊裡最輕的（更輕的邊都已經看過了，而看過卻沒加的邊，兩端當時就已經在同一棵樹裡），由 Corollary 23.2 它是 safe 的：加進 A，把兩棵樹合併成一棵。若 u 和 v 已經在同一棵樹裡，加進去會形成環，丟掉。「兩端在不在同一棵樹」正是 disjoint-set 資料結構的 FIND-SET，合併是 UNION，下一節講。

時間：第 4 行排序 O(E lg E)。第 2、3 行和第 5 到 8 行是 |V| 次 MAKE-SET、2|E| 次 FIND-SET、最多 |V| − 1 次 UNION，用 disjoint-set forest 總共 O((V + E) α(V))；G 連通時 |E| ≥ |V| − 1，所以是 O(E α(V))。α 長得比 lg 慢得多，α(V) = O(lg V) = O(lg E)，整體被排序主宰，是 O(E lg E)；又因為 |E| < |V|²，lg E = O(lg V)，寫成 O(E lg V)。平手的邊怎麼排會決定選出哪一棵 MST，但任何一棵 MST 都能靠某種排法選出來（習題 23.2-1：把那棵樹的邊在同權重裡排前面，Kruskal 就一定會先收它們）。權重若是 1 到 |V| 的整數，排序可以用 counting sort 做到 O(V + E)，整體變成 O(E α(V))（習題 23.2-4）。

Disjoint set：Kruskal 需要的資料結構

Disjoint-set 資料結構（第二十一章）維護一群互不相交的動態集合，每個集合用裡面某個成員當代表（representative）。三個操作：MAKE-SET(x) 建一個只有 x 的集合；FIND-SET(x) 回傳 x 所在集合的代表；UNION(x, y) 把 x 和 y 所在的兩個集合合併成一個。「u 和 v 是不是同一個集合」就是比 FIND-SET(u) 和 FIND-SET(v) 是不是同一個代表。書上第一個應用就是算無向圖的連通元件（CONNECTED-COMPONENTS：每個頂點 MAKE-SET，每條邊兩端不同集合就 UNION），和 Kruskal 只差邊沒有排序、沒有把邊收進 A。

21.3 的做法是 disjoint-set forest：每個集合是一棵有根樹，每個節點記一個指標 x.p 指向父節點，根的 p 指向自己，根就是代表。FIND-SET 沿著 p 一路往上走到根；UNION 是把一棵樹的根接到另一棵樹的根下面（LINK）。只這樣做樹可能退化成一條鏈，FIND-SET 要 Θ(n)，所以加兩個 heuristic：

  • Union by rank：每個節點記一個 rank，是以它為根的子樹高度的上界。LINK 時把 rank 小的根接到 rank 大的根下面，rank 不變；兩邊 rank 相同時任選一邊當新的根，它的 rank 加一。這樣每棵樹的高度最多 O(lg n)。
  • Path compression：FIND-SET 走到根之後，把路上每個節點的 p 直接改成指向根。遞迴寫法只有三行：先遞迴找到根，回來的路上順便改 p。下次再查這些節點就一步到位。注意壓縮之後 rank 不再是精確的高度，只是上界，所以書上不叫它 height。

兩個一起用，m 次操作（其中 n 次 MAKE-SET）總共 O(m α(n))，α 是一個長得極慢的函數（Ackermann 函數的反函數），對任何實際遇得到的 n 都 ≤ 4，所以實務上就是線性。證明是 21.4 整節的事，這一頁不講。Workbench 的 Kruskal 模式會把每次 FIND-SET 走過的路徑、壓縮改了哪些 p、LINK 比較了哪兩個 rank 都寫出來，頂點表列出每個節點的 p 和 rank，圖上同一個集合塗同一種顏色。

Prim：一棵樹，從 r 往外長

Prim 讓 A 永遠是一棵樹，從指定的根 r 開始往外長。每一步加一條連接「樹上頂點」和「樹外頂點」的最輕邊：這條邊是 cut (VA, V − VA) 的 light edge，由 Corollary 23.2 是 safe 的。要有效率地找到它，每個樹外頂點 v 記 v.key：v 和樹上任何頂點之間最輕的那條邊的權重（沒有邊就是 ∞），v.π 是那條邊的另一端。所有樹外頂點放在一個 min-priority queue Q 裡照 key 排。每一輪 EXTRACT-MIN 拿出 key 最小的 u，(u.π, u) 就是那條 light edge，u 進入樹；然後掃 u 的鄰居，還在 Q 裡的 v 若經由 u 有更輕的邊，就更新 v.key 和 v.π，這就是 priority queue 的 DECREASE-KEY。

書上的寫法把 A 藏在 π 裡：A = {(v, v.π) : v ∈ V − {r} − Q}，也就是每個已經出 Q 的頂點（根除外）和它的 π 連成的邊。Loop invariant 有三條。第一，A 就是上面那個式子；第二，已經在樹上的頂點就是 V − Q；第三，對 Q 裡每個 v，若 v.π ≠ NIL 則 v.key < ∞，而且 v.key 是連接 v 和樹的 light edge (v, v.π) 的權重。第 7 行取出的 u 因此是穿過 cut (V − Q, Q) 的 light edge 在樹外的那一端，第 8 到 11 行在 u 進樹之後把第三條維護好。它和第二十四章的 Dijkstra 幾乎一模一樣，差別只在 key 的意義：Prim 的 key 是「連到樹的那一條邊」的權重，Dijkstra 的是「從來源走到這裡的整條路」的長度。

時間看 Q 怎麼實作。用 binary min-heap（第六章）：第 1 到 5 行建 Q 是 O(V)；|V| 次 EXTRACT-MIN 共 O(V lg V)；第 8 到 11 行總共掃過 2|E| 個 adjacency list 項目，「v ∈ Q」用每個頂點一個 bit 就能 O(1) 判斷，每次更新是一次 DECREASE-KEY O(lg V)，共 O(E lg V）；總共 O(E lg V)，和 Kruskal 一樣。用 Fibonacci heap，DECREASE-KEY 攤銷只要 O(1)，就是 O(E + V lg V)，在 |E| 遠大於 |V| 時比較好（習題 23.2-3：|E| = ω(V) 才有差；稠密圖 |E| = Θ(V²) 時是 O(V² lg V) 對 O(V²)）。稠密圖還有更簡單的做法：用 adjacency matrix，不用 heap，每一輪線性掃一遍找 key 最小的頂點，O(V²)（習題 23.2-2）。

實作上另一個常見的寫法是不用 DECREASE-KEY：發現更好的邊就直接再 push 一個 (w, v) 進 heap，EXTRACT-MIN 拿到已經在樹上的頂點就跳過。Heap 裡最多 O(E) 個項目，時間還是 O(E lg E) = O(E lg V)，好處是任何現成的 priority queue 都能用。Workbench 照書上的寫法用 DECREASE-KEY；key 平手時用 G.V 的順序打破，真的 heap 不保證這件事，所以平手時選出的樹可能和你手算的不同，但總權重一定一樣。

MST-KRUSKAL(G, w)
1  A = ∅
2  for each vertex v ∈ G.V
3      MAKE-SET(v)
4  sort the edges of G.E into nondecreasing order by weight w
5  for each edge (u, v) ∈ G.E, taken in nondecreasing order by weight
6      if FIND-SET(u) ≠ FIND-SET(v)
7          A = A ∪ {(u, v)}
8          UNION(u, v)
9  return A
MAKE-SET(x)
1  x.p = x
2  x.rank = 0

UNION(x, y)
1  LINK(FIND-SET(x), FIND-SET(y))

LINK(x, y)
1  if x.rank > y.rank
2      y.p = x
3  else x.p = y
4      if x.rank == y.rank
5          y.rank = y.rank + 1

FIND-SET(x)
1  if x ≠ x.p
2      x.p = FIND-SET(x.p)
3  return x.p

Disjoint-set forest 的四個程序是 21.3 的寫法：union by rank 在 LINK，path compression 在 FIND-SET 的第 2 行。

MST-PRIM(G, w, r)
1  for each u ∈ G.V
2      u.key = ∞
3      u.π = NIL
4  r.key = 0
5  Q = G.V
6  while Q ≠ ∅
7      u = EXTRACT-MIN(Q)
8      for each v ∈ G.Adj[u]
9          if v ∈ Q and w(u, v) < v.key
10             v.π = u
11             v.key = w(u, v)

第 5 行把所有頂點放進 Q，第 11 行改 key 時 Q 要跟著調整，所以 Q 得支援 DECREASE-KEY。A 沒有明寫，它是 {(v, v.π) : v ∈ V − {r} − Q}。

結語

    
MST 的理論核心只有一個定理：respect A 的 cut 上的 light edge 對 A 是 safe 的，證明是把 MST 裡跨過同一個 cut 的另一條邊剪掉、換成它。Kruskal 和 Prim 都是不斷加 light edge，差別在怎麼找。Kruskal 把邊照權重排好掃一遍，每條邊問一次「兩端是不是已經同一棵樹」，所以需要 disjoint set，union by rank 加 path compression 讓這個問題幾乎是 O(1)。Prim 固定從一棵樹往外長，每個樹外頂點記住自己連到樹的最輕邊，所以需要能 DECREASE-KEY 的 min-priority queue。兩者用 binary heap 都是 O(E lg V)，差別在常數和圖的形狀：邊很多時 Prim 配 Fibonacci heap 或矩陣版佔優勢，邊少或邊已經排好序時 Kruskal 幾乎是線性。

    
Prim 的骨架把 key 的定義從「連到樹的一條邊」換成「從來源走來的整條路」就是第二十四章的 Dijkstra，站內下一頁會做。Disjoint set 的 O(m α(n)) 分析在 21.4，用的是 potential method（第十七章的攤銷分析）。書後的問題還有幾個值得想：23-1 second-best MST、23-3 bottleneck spanning tree（MST 同時也是 bottleneck spanning tree，反之不然）、23-4 的三個候選演算法，其中一個是 Borůvka 的做法，每一輪讓每個元件各挑一條最輕的邊，元件數每輪至少減半，而且天生可以平行。

    
這一頁只處理無向圖。有向圖的對應問題是 minimum spanning arborescence，cut 的 greedy 論證不成立，要用 Chu–Liu/Edmonds 的演算法。Fibonacci heap 只講了時間，沒有實作；Prim 用 G.V 的順序打破 key 平手，真的 heap 不會。圖事後加邊、改權重時怎麼更新 MST（習題 23.1-11、23.2-7）也沒有碰，但 cut 定理同樣是那些答案的出發點。
