x86-64 暫存器地圖

CPU 只認得指令，它不知道哪個暫存器該放參數。那些是 ABI 的約定。點開每一個暫存器看它的別名怎麼疊、兩套 ABI 各給它什麼角色，再用幾個 C 函式逐步看參數怎麼進去。

硬體給的是格子，ABI 決定格子怎麼用

x86-64 有 16 個 64 位元通用暫存器，每一個對 CPU 來說地位相同。mov rdi, 5 和 mov rcx, 5 都是合法指令，CPU 不會偏好哪一個。

但編譯器需要一個約定，讓 caller 和 callee 對得上：參數放哪、回傳值放哪、呼叫過後哪些暫存器還能信。最後這一點把 rsp 以外的每個暫存器分成兩類：callee-saved 是被呼叫的函式要負責還原的，caller-saved 是呼叫方自己要先存好的。參數和回傳值暫存器都屬於後者。Linux、macOS、BSD 用 System V AMD64 psABI，Windows 用自己的 Microsoft x64。下面的地圖可以切換兩套標籤，同一批暫存器會換上不同顏色。

別名不是副本，是同一塊的一部分

eax 就是 rax 的低 32 位元，ax 是低 16 位元，al 是最低 8 位元。寫 al 會直接改到 rax 的最低一個 byte。這是 8086 → 80386 → x86-64 三代擴充留下來的疊層。

唯一一條不對稱的規則：寫 32 位元別名會把高 32 位元清零，寫 16 或 8 位元別名則保留高位元不動。所以 mov eax, 1 之後整個 rax 就是 1，編譯器也因此常用 xor eax, eax 來清空 rax，省一個 byte。xor eax, eax 編碼成 2 bytes，xor rax, rax 要多一個 REX prefix 變 3 bytes，mov eax, 0 是 5 bytes。清零的效果三者相同。

結語

    
十六個通用暫存器對 CPU 是平等的，參數、回傳值、callee-saved 這些角色都是 ABI 的約定，所以同一份 C 原始碼在 SysV 和 Win64 下會編出不同的暫存器用法。別名是同一塊的一部分，不是副本；寫 32 位元別名會清掉高 32 位元，寫 16 或 8 位元不會。

    
call 和 ret 怎麼搬動 rsp 和 rip、frame 怎麼疊，在函式呼叫與 stack 那一頁；暫存器數量和呼叫慣例在三個 ISA 之間怎麼取捨，在 ISA 比較系列。

    
範例只用整數和指標參數，沒有浮點、struct 傳值和可變參數的規則。地圖只畫通用、控制和向量暫存器，沒畫的還有：區段暫存器 cs ds es ss fs gs，64-bit 模式下前四個基底固定為 0，fs、gs 保留 base，Linux 用 fs 指向 thread-local storage，Windows 用 gs 指向 TEB；x87 的 80-bit 浮點堆疊 st0–st7 和跟它共用同一塊實體空間的 MMX mm0–mm7，long double 才會用到；AVX-512 的遮罩 k0–k7，向量指令的 per-lane 開關，k0 代表不遮罩；APX 的 r16–r31，2024 年起 Intel 新增的 16 個通用暫存器，需要 CPU 與 OS 支援，還不在 SysV 預設 ABI 內；AMX 的 tmm0–tmm7，每個最大 1 KB 的矩陣 tile；以及只有 kernel 能碰的控制暫存器 cr0 cr2 cr3 cr4 cr8、除錯暫存器 dr0–dr7、描述表 gdtr idtr ldtr tr，和用 rdmsr/wrmsr 存取的上千個 MSR（例如 IA32_EFER、IA32_LSTAR）。
