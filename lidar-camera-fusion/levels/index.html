融合層級：相機資訊從哪裡接進來

LiDAR 和相機融合的方法名字很多，但拆開來看，幾乎都是同一條 LiDAR 偵測管線，差別只在相機資訊從哪一段接進來。接得越早，兩邊綁得越緊，外參一不準就出錯；接得越晚，兩邊越獨立，但能互補的東西也越少。

調研資料截至 2026 年 11 月 5 日。由 Claude 整理公開論文、官方文件和程式庫後撰寫。

融合層級的分類和各方法的機制不會過期；benchmark 數字、方法間的優劣和 repo 的維護狀態會隨新方法出現而改變。標成【工程判斷】的是撰寫者的推論。

兩個感測器各缺什麼

LiDAR 直接量到每個點的 3D 位置，幾何很準，但點很稀疏：遠處的行人可能只有幾個點，而且看不到顏色和紋理。相機剛好相反，每個像素都有豐富的外觀資訊，2D 網路很擅長認出「這是行人」，但影像本身沒有深度。融合想要的是兩邊互補：幾何交給 LiDAR，語意交給相機。

要互補，就得知道 LiDAR 的某個點對到影像上的哪個像素。這靠兩組校正參數：外參把點從 LiDAR 座標轉到相機座標，內參再把它投到像素（u, v）。外參會因為安裝、震動、溫度而漂移，所以「融合方法有多依賴這個對應關係」，就決定了它對校正誤差有多敏感。

五個接入點

一條典型的 LiDAR 偵測管線是：點雲 → 體素或柱編碼 → 3D 主幹 → BEV 特徵 → 偵測頭 → 3D 框。相機那邊是：影像 → 2D 主幹 → 影像特徵或分割 → 2D 偵測頭 → 2D 框。融合方法依相機資訊接進來的位置分成五類：

  1. 點級（early／point-level）：每個 LiDAR 點投影到影像上，取那個像素的語意分數或特徵附加到點上，再交給幾乎不改的 LiDAR 偵測器。
  2. Frustum（cascade）：先用 2D 偵測器框出物件，只在框對應的 3D 視錐裡用點雲估 3D 框。
  3. 中期（BEV 融合）：兩邊各自轉成 BEV 特徵圖，在同一張格子上合併。
  4. Query 融合：Transformer 的物件 query 同時去兩邊的特徵裡查資料，對應關係用 attention 學出來。
  5. 晚期（late／object-level）：兩邊各自偵測完，再把 2D 框和 3D 框配對、重新評分。

越往前接，點和像素的對應越「硬」：外參錯一點，點就被塗上錯誤的語意，而且後面的網路分不出來。越往後接，兩個分支越獨立，可以各自訓練、各自替換，任一個感測器壞掉時自然退化成單一感測器；代價是特徵層級的互補（例如 LiDAR 稀疏的地方由影像補出物件）用不到。

看一個融合方法的六個問題

比較融合方法時，與其看 leaderboard 的名次，不如對每個方法問同樣六個問題。前三個問結構，後三個問它怎麼壞：

  1. 相機分支輸出什麼？（類別分數、CNN 特徵、深度、2D 框）
  2. 接到 LiDAR 管線的哪一段？
  3. 點和像素怎麼對應？（固定的投影、學出來的 attention、還是框和框配對）
  4. 外參不準時會怎樣？
  5. 相機壞掉時會怎樣？
  6. LiDAR 壞掉時會怎樣？

結構
    怎麼壞

      點級：把影像資訊塗到點上

      點級方法的共同機制是：每個 LiDAR 點用外參加內參投影到影像上，取該像素的影像資訊附加到點的特徵後面，再交給（幾乎）不改的 LiDAR 偵測器。差別在 2D 網路輸出什麼、接到 LiDAR 分支的哪一段。

      PointPainting 是最乾淨的版本：附加的是語意分割的類別分數，影像網路和 LiDAR 網路完全解耦，偵測器只要把輸入通道數改大。它在 KITTI val 的 BEV moderate 上讓 PointPillars 的行人 +4.57、自行車 +2.84，但車幾乎沒變（+0.08）；nuScenes test 上 PointPillars 加 painting 多 6.3 mAP【論文自報】。用前一張影像的分割結果做 pipelining，只多 0.75 ms，精度不掉，而且偵測增益和分割品質（mIoU）正相關。PointAugmenting 和 MVX-Net 改附加更高維的 CNN 特徵，資訊比較豐富，但和影像網路綁得更緊。MVP 和 VirConv 則反過來，用影像替點雲補出虛擬點；EPNet 和 Focals Conv 把融合放進 3D 主幹內部。

      點級方法需要外參、內參，以及時間同步的點和像素。它們的共同弱點也來自這裡：對應關係是寫死的投影，外參一偏，點就被塗上錯誤的語意，後面的網路沒有辦法分辨。相機壞掉時，painting 通道變成雜訊或零，LiDAR 偵測器收到訓練時沒見過的分佈。TransFusion 論文把 PointAugmenting 式融合裝到同一個 LiDAR 主幹上測，6 張影像全掉時 mAP 降 17.2；逐點 concat 降 23.8。外參誤差的數字在穩健性那一頁。

      另一個不會報錯的陷阱是資料增強。旋轉、翻轉、縮放、GT-sampling 這些幾何增強都改了點的位置，投影時必須能反推回原始座標，否則點會對到錯的像素。DeepFusion 的消融顯示，不做這個反推（InverseAug）時，行人 L2 APH 只有 63.5，幾乎等於 LiDAR-only 的 63.0；做了才是 67.0【論文自報】。對齊做錯時融合增益會悄悄消失，訓練照樣收斂。

      Frustum：先 2D 再 3D

      Frustum PointNets 和 Frustum ConvNet 先用 2D 偵測器框出物件，再只在框對應的 3D 視錐裡用點雲估 3D 框。這很適合單一前相機的配置（它們都從 KITTI 起家），但召回率被 2D 偵測器封頂：F-PointNet 原文承認，暗光或嚴重遮擋時 2D 偵測器漏掉的物件，3D 也不會偵測到。相機失效就等於整個偵測失效，所以不適合當唯一的偵測路徑。兩個 repo 都已多年沒有更新（最後 push 分別在 2020 年 3 月和 12 月）。

      BEV 融合：在同一張地圖上合併

      BEVFusion（MIT）是這一類的代表：相機特徵用 LSS（估每個像素的深度分佈，再 pooling 到 BEV 格子）轉成相機 BEV，LiDAR 走體素到 BEV，兩張圖 concat 後用卷積融合，接 TransFusion head。它沒有逐點對應，外參誤差的效果是整塊相機 BEV 特徵平移，LiDAR BEV 不受影響，所以校正敏感度中等。但不同評測對它的敏感度給出互相矛盾的結論，細節在穩健性那一頁。

      它的官方 repo 已經 archived（最後 push 2024 年 7 月），但 mmdet3d、OpenPCDet、NVIDIA 三個獨立 codebase 都重現了接近的數字（nuScenes val mAP／NDS 分別是 68.6／71.4、67.75／70.98、68.52／71.38）【第三方重現】，NVIDIA 還有 TensorRT 版。論文聲稱比 TransFusion 少 1.9 倍 MACs、延遲低 1.3 倍，在 RTX 3090 上 8.4 FPS。相機分支的深度 bin 和影像解析度、焦距有關，換相機要重調；NVIDIA V2XFusion 的文件就明確要求換資料集時調整 dbound。

      同一類的其他方法各自補一個弱點：ADLab 的 BEVFusion 把兩條 stream 設計成可以獨立運作，目標是 LiDAR 失效時相機 stream 仍能偵測，但需要用 robust augmentation 微調；GraphBEV 專門處理外參誤差；DAL 主張相機只輔助分類、框的幾何全靠 LiDAR；UniBEV 用正規化的權重取代 concat，讓缺一個感測器時不用重訓。LiDAR 失效時，這一類沒做 modality dropout 訓練的模型會崩。

      Query 融合：讓 attention 去找對應

      TransFusion 分兩階段：先用 LiDAR 的 BEV heatmap 初始化物件 query 並產生初始框，再讓 query 用 cross-attention 去影像特徵裡精修。相機只負責精修，所以它對相機雜訊和外參誤差非常穩：camera 到 LiDAR 平移誤差 1 m 時只掉 0.49 mAP。代價是相機的貢獻也很小，nuScenes test 上只比 LiDAR-only 多 1.5 NDS，而且 LiDAR 一掉就完全無法運作，因為 query 的初始化整個靠點雲。

      CMT 沒有顯式的視角轉換，影像和點雲 token 都加上 3D 位置編碼後直接送進 DETR decoder，再加上 masked-modal training（訓練時隨機遮掉某個感測器）。它在 nuScenes test 上 74.1 NDS（單模型）【論文自報】，在第三方的 MultiCorrupt 評測裡穩健性排第一，但沒有官方 TensorRT 實作。FUTR3D 用 3D reference point 去各感測器取樣特徵，支援任意感測器組合，相機加 4 線 LiDAR 就有 58.0 mAP，高於 32 線的 CenterPoint（56.6），對低線數 LiDAR 有參考價值。MetaBEV 和 MoME 針對缺感測器設計，MoME 用三個 expert decoder（只相機、只 LiDAR、兩者）讓 router 依特徵品質替每個 query 選一個。

      反例是 DeepInteraction 這種早期雙向互動：相機雜訊會透過互動污染整個特徵，它在 MultiCorrupt 的整體穩健性最低，霧天只剩 0.583。SparseFusion 則讓兩個感測器各自偵測出稀疏的候選，再用輕量的 self-attention 融合，結構上接近「可學習的晚期融合」，MultiCorrupt 的作者認為它的穩健性就來自兩條平行分支。

      晚期融合：各自偵測完再配對

      CLOCs 在 NMS 之前，把任意 2D 偵測器和任意 3D 偵測器的候選框組成稀疏張量（2D 和 3D 框投影後的 IoU、兩邊的分數、距離），用一個小 CNN 重新評分 3D 候選，只多不到 3 ms。沒有 2D 對應的 3D 候選不會被丟掉，而是把 IoU 和 2D 分數設成 −1，讓網路分得出「相機沒看到」和「IoU 很低」。它的增益隨 LiDAR 基線變強而遞減：KITTI test 的 Car 3D moderate，SECOND +5.90、PointRCNN +1.04、PV-RCNN 只有 +0.39【論文自報】。官方 repo 只支援 KITTI 和 SECOND，不過邏輯很小，重寫不難。

      Autoware 的 autoware_image_projection_based_fusion 是規則式的晚期融合：用 2D ROI 更新 3D 物件的類別、替 LiDAR cluster 指定類別，也有 pointpainting 節點，而且附完整的時間同步機制（每相機的 timestamp offset、timeout、matching window）。它是少數有實車產品經驗、持續維護的開源參考實作。

      晚期融合的優點是兩個感測器可以各自訓練、驗證、替換，任一個壞掉時自然退化，校正誤差只影響「配對」，不影響 3D 幾何；缺點是用不到特徵層級的互補，分數上限較低。但有一個必須說清楚的證據缺口：Yu et al.、Dong et al.、MultiCorrupt 這幾個穩健性 benchmark 都沒有評測晚期融合。「晚期融合比較穩健」目前是結構推論加業界實務，沒有同一協定下的直接數字【工程判斷】。

      方法比較表

      「多 sweep」一欄指方法是否依賴多個 sweep 的時戳。沒有任何方法需要 LiDAR 的 Doppler 速度欄位；nuScenes 的官方設定普遍用 10 個 sweep 加 Δt 通道來預測速度（例如 mmdet3d 的 BEVFusion config 和 OpenPCDet 的 nuScenes config），這是設定問題，可以改成單 sweep 並拿掉 velocity head，但多 sweep 累積本身需要 ego pose。

      結語

      融合方法的差別，說到底是相機資訊接在 LiDAR 管線的哪一段、點和像素怎麼對應。接得越早，對應越依賴固定的投影，外參不準時越容易悄悄出錯；接得越晚，兩邊越獨立，越容易各自替換和退化，但能從影像拿到的增益也越少。最穩健的融合方式和增益最大的融合方式往往不是同一個。

      這一頁只比較了結構。每個方法實際上壞得多嚴重，要看合成腐化的評測數字，那些數字彼此還常常矛盾，見穩健性；換一台車或搬上嵌入式平台會遇到的問題，見從論文到車上。
