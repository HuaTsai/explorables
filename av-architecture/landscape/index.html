六種架構，誰在車上跑哪一種

發表會上的「端到端」範圍很寬：有人把多任務感知網路叫端到端，有人指的是一個網路直接從感測器輸出軌跡。這一頁先照「哪些部分是學習的、模組之間傳什麼」把架構分成六類，再看 2025–2026 年實際上路的系統各屬於哪一類、證據有多硬。

調研資料截至 2026 年 11 月 5 日。由 Claude 整理公開論文、公司官方資料、新聞報導和標準文件後撰寫。

六類架構的定義不會過期；誰部署了什麼、各公司的宣稱和比較表的評等會變。公司的說法都是截至這一天的狀態，證據日期附在每一列，超過六個月的業界說法引用前請重新查證。標成【工程判斷】的是撰寫者的推論。

「端到端」指的範圍很寬

要比較架構，先得把名詞分清楚。依「哪些部分是學習的」和「模組之間的介面是什麼」，可以分成六類：

類型定義中間介面代表
A. 傳統模組化各任務各自一個網路或演算法（2D／3D 偵測、車道、追蹤、預測），由手寫的 fusion／tracking 串接，planner 用規則或最佳化明確、人可讀（object list、lane graph）Autoware Universe、Apollo（早期）、2010 年代多數 ADAS
B. 多任務 BEV 感知多感測器 → 共用 backbone → BEV／3D 特徵 → 多個任務 head（3D 偵測、地圖元素、occupancy、運動預測）。規劃仍是獨立模組明確（各 head 的輸出）BEVFusion、BEVFormer
C. 兩段式 E2E感知、預測、規劃都是神經網路，以可微分方式串接、聯合訓練到規劃目標，但中間仍有明確的 query 或輸出可以監督明確和潛在特徵並存UniAD、VAD、SparseDrive；中國業界說的「兩段式端到端」
D. 一段式 E2E感測器 → 單一網路 → 軌跡（或控制）。可以帶輔助 head（depth、seg、偵測）幫助訓練和視覺化，但規劃不依賴這些明確輸出主要是潛在特徵TransFuser、Tesla FSD v12+、Horizon HSD
E. VLM／VLA以多模態大型語言模型為骨幹，輸出軌跡和／或語言推理；常以「快慢雙系統」部署語言 token 或潛在 tokenEMMA、DriveVLM、Alpamayo-R1、LINGO-2
F. 混合（含獨立安全層）以 B、C、D、E 任一種為主系統，外加獨立、較簡單、可驗證的安全監控或 fallback 堆疊主系統的輸出，加上安全層自己的明確世界模型NVIDIA DRIVE AV 加 Halos、Waymo 的 validation layer、Mobileye PGF、Autoware 的 hybrid 架構

有四個地方常被混在一起。

第一，「感知端到端」不等於「端到端自駕」。2021–2022 年 Tesla 的 HydraNet、occupancy network 和多數中國 BEV 方案屬於 B 類，規劃仍是手寫或最佳化。把 B 類稱為「端到端」，是行銷用語的延伸。

第二，「輸出軌跡」不等於「輸出控制」。公開的學術 E2E 模型幾乎都輸出軌跡或 waypoints，再交給 PID 或 MPC 控制器，例如 TransFuser 用 PID 追蹤預測的 waypoints。真正從感測器直接輸出方向盤和油門的量產系統，沒有公開證據。

第三，一段式 E2E 通常仍有輔助輸出。TransFuser 用 depth、semantic segmentation、HD map、車輛偵測當輔助任務，作者明說是為了可解釋性和強健性；拿掉全部輔助 loss 後，route completion 從 92.28 掉到 78.17【論文自報】。Tesla 在 ICCV 2025 的演講，據 36Kr 的報導也展示了 3D occupancy、panoptic segmentation、3D Gaussian 和語言等輔助輸出【二手】。

第四，VLA 的「L」正在被拿掉。XPeng 的 VLA 2.0 官方描述為「end-to-end vision-to-action architecture」，去掉了中間的翻譯層【一手】（2026 年 3 月）；Huawei 則主張跳過語言、直接走 WA（World-Action）路線【二手】（ChinaEVHome）。

分類一個系統的四個問題

拿到一個系統的公開描述，要放進上面哪一類，依序問四個問題：

  1. 哪些部分是學習的？
  2. 模組之間傳的是什麼：人讀得懂的明確輸出（object list、車道、occupancy），還是潛在特徵？
  3. 規劃是手寫規則或最佳化，還是學出來的？
  4. 有沒有一個獨立於主系統、比較簡單、可以驗證的安全層？

前兩題就是上表的分類軸，第 3 題把 B 和 C 分開，第 4 題把 F 和其他五類分開。下面的工作台對每一類回答這四題，並列出業界部署總表裡被歸到這一類的系統。

類型

綠底方塊是學習式元件，綠色虛線框是「網路或演算法都有」，灰框是手寫的規則、最佳化或控制器。箭頭下方標「明確」是人讀得懂的輸出，「潛在」是潛在特徵，「兩者」是並存。控制一律畫成 PID／MPC，因為沒有公開證據顯示量產系統直接輸出方向盤和油門。圖只畫資料流的大致分段，不是任何一家的實際架構。

      誰「真的」在跑什麼

      有人監督的 L2、L2+：一段式 E2E 已是行銷主流，中國市場尤其明顯。Tesla、Horizon、Momenta、XPeng、Huawei、Li Auto 都宣稱 E2E 或 VLA 已經量產。但這些全是 SAE L2，駕駛人負責監督，安全論證可以靠駕駛人接管：XPeng 官方明說「remains a supervised intelligent driving system」，Horizon 也寫「Car drives, human supervises」。外部也無法驗證「是否真的沒有規則層」：連最激進宣稱「去除規則兜底」的 Horizon HSD，據報導也仍保留輕量後處理和安全驗證模組【二手】（2025 年 8 月）。也就是說，「沒有規則」通常是指沒有規則式規劃，不是沒有安全檢查；AEB 這類被動安全功能通常仍是獨立的法規功能，例如 Horizon 的產品頁另外列出「Proactive Safety Always ON」。此外，中國廠商的「一段式」「VLA」「WA」定義並不一致，資料多是發表會說法，缺少論文等級的技術揭露。

      無人 L4：唯一規模化營運的 Waymo 明確走混合路線。Waymo 的 Foundation Model 本身是大型學習模型（有 VLM、有 world decoder），但它保留並使用物件、語意屬性、roadgraph 這些結構化表示，有獨立的 onboard validation layer 驗證生成的軌跡，並透過蒸餾得到較小的車端 Student 模型，再用 Simulator 加 Critic 以 RL 訓練 Driver。這不是放棄 E2E，而是 E2E 式的大模型、可監督的中間表示、獨立驗證三者並存。早在 2018 年，Waymo 的 ChauffeurNet 就用感知輸出這種中層表示當輸入，並指出純模仿學習不夠，必須合成擾動過的「最差」情況。

      供應商的量產架構都含獨立安全堆疊。NVIDIA 給 OEM 量產的 DRIVE AV 明確是「E2E 加平行的 classical safety stack」，並宣稱 DriveOS 6.0 符合 ISO 26262 ASIL D（NVIDIA）。Mobileye 的 PGF 是 Primary、Guardian、Fallback 三層。需要向車廠交代安全案例的供應商都這樣做，原因見安全層那一頁。

      Tesla 的公開技術資訊其實很少。v12 release note 的「single end-to-end neural network」是一手文字，之後關於輔助輸出、世界模擬器的細節都來自演講的二手轉述。Robotaxi 營運（2025 年 6 月起附安全監控員、2026 年 1 月起部分無人）也只有二手報導（Teslanorth），沒有可比的公開安全數據。Tesla 的證據是 L2 的使用體驗和自報數據；它的資料量（數百萬段 clip 加上百萬級車隊）是它選這個架構的前提，不是結果。不應把 Tesla 當成「E2E 已被證明可以無人化」的證據。

      收斂方向。原本主打 E2E 的玩家都在補結構和安全層：Wayve 據報導自述 E2E 不足以保證規模化安全，Tesla 據報導展示可以探查的中間輸出。原本主打模組化的玩家則都把模組換成大模型：Mobileye 在模組內用 E2E 學習、Waymo 用 foundation model、Autoware 把 E2E 列為主模式。終點看起來是同一個地方：學習式核心、結構化中間表示、獨立安全層。

      結語

      2025–2026 年實際上路的主流是混合架構，不是純端到端，也不是 2018 年那種純模組化：一個大型學習式核心（BEV 多任務網路，或從感測器到軌跡的大模型），保留明確的中間表示（物件、地圖元素、occupancy），再外掛一個獨立、可驗證的安全層。一段式 E2E 目前只在有人監督的 L2 量產，駕駛人就是最後的 fallback。過時的是「每個任務一個獨立小網路，加上大量手寫 fusion」，不是「明確介面」；比起「端到端還是模組化」，更能區分架構的是三件事：中間表示是否明確、規劃是否學習、有沒有獨立安全層。

      多任務 BEV 感知（B 類）本身怎麼融合 LiDAR 和相機，見 LiDAR 與相機融合 3D 偵測系列。各類架構的「穩定」有多少學術證據，見評估那一頁；安全層為什麼是標準配備，見安全層那一頁。

      這一頁沒能確認的事：Tesla FSD v13、v14 的確切架構（是否仍有規則式安全層、輔助輸出做什麼用）沒有一手技術揭露；中國廠商的「一段式」「VLA」「WA」多半只有發表會說法，是否保留規則 fallback 各家說法不一或沒有揭露；Autoware 2.0（2026 年 11 月 2 日發布）只取得二手報導，使用前請直接查 GitHub release notes 和 docs.autoware.org；NVIDIA DRIVE AV 在美國的實際上市狀態（官方 2026 年 1 月稱「by end of this year」）沒有查證。
